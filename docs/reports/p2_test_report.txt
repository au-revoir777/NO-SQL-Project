## e2e timing note (found while writing this report)
Two earlier local Playwright runs failed: a sign-in and a create-user request
were still pending when the 5 s / 10 s assertion timeout expired. Diagnosis,
with a request timer and a thread-stack watchdog around the e2e API
(diagnostic wrapper, not committed):
- the slow requests were inside argon2 `verify_secret`, not deadlocked; one
  login took 5.41 s while Chromium and `next start` were busy (0.16-0.22 s per
  hash when the machine is idle);
- the auth and admin handlers were `async def`, so every hash also blocked the
  event loop for all other requests.
Fixes: those handlers are now plain `def` (FastAPI threadpool), and the
Playwright assertion timeout is 15 s. The argon2 parameters were not lowered.
After the fix: 20/20 in a 4x repeat (with the watchdog) and 15/15 in the 3x repeat above.
A 50-iteration concurrent load test of csrf/refresh/login/page/logout through the
Next.js BFF and a 134 s run with 4-6 s idle gaps between requests had no errors
and no request slower than 3 s.

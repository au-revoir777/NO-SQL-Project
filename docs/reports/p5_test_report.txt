## Acceptance criteria
- State machines enforced by the API, with 409 invalid_transition listing the allowed targets; closing
  a case without a resolution is a 422; only admins reopen: test_alert_transitions,
  test_case_transitions, test_only_admins_reopen, test_closing_a_case_needs_a_resolution (pytest); the case form refuses to close without a resolution (Vitest
  forms.test.ts, Playwright cases.spec.ts).
- Alerts recorded from a real baseline run (seed 7), filters and saved views: tests/test_cases.py.
- Label feedback: confirm/dismiss on the current run returns AlertPolicy.feedback's result, equal to
  the same feedback applied to a deep copy of the policy (pytest); the alert page shows the
  threshold before and after (Playwright).
- Scripted triage session (status, assignment, labels, notes with an edit, case, attachment,
  transitions) verified through GET /api/v1/audit/verify and `fraudsim audit-verify` (pytest).
- Playwright: an analyst opens the top alert, reads the evidence table, adds a note, labels it,
  creates a case and escalates it; an admin finds CASE_CREATED and CASE_UPDATED for that case in the
  audit view and the chain verifies.
- axe: no serious/critical violations on /alerts, /alerts/[id] (activity tab), /cases/[id], /cases
  and /audit.

## Fixed while testing
- Toggling the evidence graph to its table showed nothing: React reused the graph's container and
  Cytoscape's cleanup emptied it. The two views now have their own keyed elements.
- App-database times have no offset (SQLite drops it), so the browser read them as local time and
  case times were shifted by the UTC offset. The web app now reads them as UTC (parseTime, Vitest).
- The audit table scrolled sideways once it had long entries (axe scrollable-region-focusable);
  the details column now wraps.

## Observations (not changed in P5)
- The queue shows a ring's latest risk, not its risk when it was raised. In the seed-7 baseline run
  one alert (raised as kind "alert") now reads 0.00 in bucket 0.0-0.1; the ring timeline on its page
  holds the earlier scores.
- The API's current run counts as live for label feedback even after it has finished, so labels on
  its alerts still adjust that run's in-memory policy (as pytest expects).
